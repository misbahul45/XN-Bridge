# Career workflow

The fixture workflow exercises PKL/internships end to end; categories also include paid/remote/research internships, graduate, entry-level, junior and part-time opportunities. Locations and hard constraints are inputs; Indonesia is an optional localization, not a fixed market.

1. **Profile:** use an existing extractor for PDF/DOCX. Register its exact text against the original local source and pass `text`, `extractor` and `evidence_id` to `profile.ingest`. The bridge binds workflow/digest and versions changes, including contact-only edits. Direct `.md`/`.txt` input is supported. Confirm unknown personal facts using the user's actual words; extraction does not create work authorization or availability.
2. **Campaign:** `campaign.define` separates strict requirements/preferences, normalizes category/location/remote settings, rejects conflicts and emits bounded deduplicated queries.
3. **Companies:** the host calls an existing search provider, then `companies.add`. Exact normalized names/domains deduplicate identities. `company.verify_domain` requires fresh evidence from the asserted domain; a company existing is not evidence of hiring.
4. **Opportunities:** reuse `career.listings` where healthy, or use `opportunities.fetch_ats` for verified-company Greenhouse/Lever/Ashby boards. Otherwise capture public page evidence and call `opportunities.ingest`. Status is OPEN_VERIFIED, LISTED_UNCERTAIN, EXPIRED, INQUIRY_ONLY or UNKNOWN. Stale or unsupported data cannot be promoted to OPEN_VERIFIED.
5. **Matching:** `match.run` reports failed/unknown hard constraints before skill/project/preference scores. An unknown authorization requirement stays unknown; a high score cannot hide ineligibility.
6. **Preparation:** `application.prepare` builds a fact pack and draft skeletons; `draft.check` flags unsupported claims. Existing document generators export the prepared content. Snapshot parsing and `form.plan` classify text, textarea, select/radio/checkbox, upload and user-only declaration actions. CAPTCHA, login and unsupported sensitive answers require a person.
7. **Supervision:** `submission.prepare` binds content, attachments, declarations and destination into a manifest. Real submission stays manual with the current host boundary. The human approval CLI and execution lifecycle are implemented and tested against a local function fixture; no employer endpoint is invoked by the tests.
8. **Tracking:** record explicit status/evidence and history. Successful submission needs confirmation; ambiguous results become OUTCOME_UNKNOWN and require reconciliation. Read-only Gmail tools are installed but AUTH_REQUIRED until owner OAuth. Prepared emails remain local drafts. Failed browser integration degrades to prepared content and links.

Verified runs: `dry-run career` passed 20 checks; timeout/reconciliation passed 22; `dry-run research` passed five using the same generic engine. Actual installed document providers generated a synthetic PDF, extracted it, and ingested a provenance-bound profile. The PDF was separately rendered and visually inspected.
